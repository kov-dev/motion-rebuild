# Шаблон аналізу секції — `docs/sections/<section>.md`

Заповнює субагент (sonnet) після читання одного Figma-фрейму + відповідного
шматка лайву. Коротко, фактами, без прози. Усе в px макета (у Webflow → /100 rem).

```
# <Section>

## Джерела
- Figma: <node-id>, розмір фрейму, скільки станів/кадрів у фреймі
- Лайв: id секції, запис reference/recordings/<section>.gif

## Структура (дерево з ролями)
- section-<name>
  - <role> — тег, що всередині

## Токени, що зустрілись (ім'я в Figma → значення)
- кольори / шрифти / відступи / радіуси

## Розкладка
- контейнер, ширини, гепи, вирівнювання; відмінності 1440 / 768 / 375

## Ассети
- svg / lottie / відео / картинки — ім'я, розмір, звідки взяти (оригінал Webflow assets чи Figma export)

## Анімація (розкадровка з Figma + що реально на лайві)
- тригер → ціль → властивість → тривалість/ease → IX3 чи код (і чому)

## Розбіжності Figma ↔ лайв
- що на лайві не так, як у макеті (беремо лайв як істину, якщо не сказано інакше)

## Питання до користувача
```
